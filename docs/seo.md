# Индексация каталога в Google и Яндексе

Публичные адреса сохраняются: `/product/{id}`, `/catalog/{slug}`, `/catalog`,
`/categories` и `/`. Товары открываются по прямым ссылкам из поиска.

Сервер возвращает HTML с содержимым и метаданными всем посетителям, независимо
от User-Agent. React затем подключает интерактивный интерфейс. HTML содержит
публичную розничную цену; персональная скидка применяется после входа.
Скрытые/удалённые товары не входят в sitemap и возвращают 404. Технические
ошибки возвращают 503, чтобы поисковик не считал товар удалённым.

## Старые ссылки Satu из поисковой выдачи

Адреса `/p{старый_id}-{название}.html` (также `/p{старый_id}.html`)
обрабатываются backend и возвращают 301 на `/product/{id}` только при наличии
проверенного соответствия в `legacy_product_urls` и доступного публичного товара.
Название в старом URL не используется для поиска: оно могло меняться и не уникально.
Старый ID нельзя подставлять в новый URL — это другая нумерация.

Миграция V110 добавляет подтверждённую ссылку
`/p131540811-rezba-kor-chernaya.html` для артикула 559. Остальной старый каталог
нужно сопоставить по исходной выгрузке Satu с ID/URL и артикулами и добавить
проверенные пары в новой миграции. Соответствие хранит ID текущего товара, чтобы
последующее изменение или повторное использование артикула не подменило назначение.
Неизвестные ссылки, скрытые и удалённые товары возвращают 404 с `noindex`;
ошибка БД — 503. Массового перенаправления на главную или случайный товар нет.

Для применения нужны backend с миграцией и обновлённый Nginx; в локальной среде
также обновляется gateway. После публикации проверьте старый URL без следования
редиректам: статус 301 и `Location: /product/{id}`, затем статус 200 и правильный
товар по адресу назначения. Sitemap продолжает содержать только новые адреса.

## Конфигурация и публикация

- В production задайте `APP_SEO_SITE_URL=https://mstop.kz` (или реальный основной
  домен). Домен должен совпадать с публичным HTTPS-адресом; www перенаправляется
  на основной домен.
- Backend загружает оболочку текущей сборки из
  `APP_SEO_TEMPLATE_URL=http://frontend:8080/index.html`. Отдельная внутренняя
  сеть `seo-template` соединяет только backend/frontend соответствующего
  blue/green слота. Не направляйте template URL на публичный `/`: получится
  рекурсивный запрос. В dev используется порт Vite из `FRONTEND_PORT`.
- Публикуются backend, frontend, Compose и Nginx-конфигурация вместе.
  `deploy/production/deploy.sh` применяет изменённые маршруты Nginx после
  переключения приложения. Не достаточно обновить только файлы React.
- Публичные страницы, `/robots.txt`, `/sitemap.xml` и `/sitemap-*.xml` должны
  попадать в backend, а JS/CSS — во frontend. Ответ HTML вместо XML — ошибка.
- Карта сайта разбивается на части по 5000 активных записей. Дочерние карты
  находятся в корне сайта, чтобы их область действия охватывала весь каталог.

Перед публикацией проверьте локальную среду, после публикации — публичную:

```sh
python3 deploy/production/check-seo.py https://mstop.kz
# Только для локального TLS с собственным сертификатом:
python3 deploy/production/check-seo.py https://localhost --insecure
```

Проверка делает только GET-запросы: robots, sitemap, первая карточка товара,
JSON-LD, canonical, наличие JS сборки и HTTP 404 для отсутствующего товара.
Она не подтверждает наличие страниц в индексе поисковика.

## Подключение поисковых кабинетов

1. Добавьте домен в Google Search Console и Яндекс Вебмастер под аккаунтами
   владельца. Для DNS-подтверждения используйте предоставленную кабинетом запись.
   Для подтверждения HTML-метатегом перенесите только значение `content` в
   `APP_SEO_GOOGLE_SITE_VERIFICATION` / `APP_SEO_YANDEX_VERIFICATION` и примените
   конфигурацию backend. Значения по умолчанию пустые.
2. Отправьте `https://mstop.kz/sitemap.xml` в оба кабинета.
3. Проверьте несколько реальных карточек через проверку URL в Search Console,
   Google Rich Results Test и проверку ответа сервера в Яндекс Вебмастере.
   Проверьте название, цену KZT, наличие, изображение и отсутствие запретов.
4. Запросите переобход главной, основных категорий и нескольких товаров.
   Затем следите за исключёнными страницами, ошибками обхода и отчётами товаров.

Описания и названия должны точно отражать товар: модель, артикул, бренд и
характеристики, если они известны. Не добавляйте выдуманные отзывы, рейтинги,
наличие, условия доставки или повторяющиеся ключевые слова. Разметка улучшает
понимание страницы, но не гарантирует расширенный сниппет или позицию в выдаче.
