# Каталог МКС

Страница: `http://localhost:5174/admin/mks-catalog`.
Сначала войдите в CRM через `/admin/login`. Откройте «Поставщики → МКС» в боковом
меню или перейдите по прямой ссылке. Раздел и пункт меню видны при наличии права
`pages.mks.view`. Сервер требует это право и активного, неудалённого пользователя,
независимо от его роли. Миграция V123 первоначально выдаёт право администратору;
для других ролей или пользователей его можно назначить через управление правами.

## Подключение

В локальном `.env` уже добавлены пустые серверные настройки:

```dotenv
APP_MKS_LOGIN=
APP_MKS_PASSWORD=
```

Заполните их данными оптового кабинета МКС. Если значение содержит пробелы, `#`
или `$`, используйте одинарные кавычки по синтаксису Docker Compose `.env`.
Файл `.env` игнорируется Git; реальные значения нельзя переносить в примеры
конфигурации, фронтенд, документацию или журналы.

После изменения `.env` из корня проекта примените окружение только backend:

```sh
docker compose up -d --no-build --no-deps backend
```

Простой restart не обновляет окружение контейнера. Затем откройте страницу и
нажмите «Подключить МКС». Успешное подключение подтверждается авторизованным
ответом инициализации каталога, а не одним ответом формы входа.

## Каталог и импорт товаров поставщика

Сохранённые товары доступны в «Товары → Товары поставщиков»
(`/admin/products/suppliers`). Импорт запускается со страницы МКС: можно отметить
товары, импортировать всю выборку по поиску и фильтрам либо весь каталог.
Выборка по фильтрам охватывает все страницы поставщика. Задания и ход импорта
сохраняются в БД; сервер постепенно загружает карточки в отдельный каталог
поставщиков. Очередь отображается на страницах МКС и товаров поставщиков и
обновляется автоматически без перезагрузки.

Повторный импорт обновляет запись по сочетанию поставщика и ID его товара.
Закупочная цена сохраняется отдельно от розничной цены: для МКС последняя
соответствует МРЦ (`price_mrc`), а не рекомендованной цене `price_rrc`. Товары поставщиков не
изменяют наши складские остатки. Подробности очереди и синхронизации:
[supplier-products.md](supplier-products.md).

- Сохранение сессии МКС в памяти backend, поиск и пагинация на стороне поставщика.
- Фильтры из ответа кабинета и подтверждённые публичным кодом переключатели,
  диапазоны цен и сортировка. Доступные значения зависят от текущей категории.
- Таблица на существующих компонентах CRM, состояния загрузки и ошибок.
- Клик по строке или кнопке «Карточка» открывает модальное окно CRM с фотографиями,
  ценами, штрихкодом, характеристиками и описанием МКС. Закрытие сохраняет поиск,
  фильтры и страницу каталога.
- «Создать под заказ» открывает обычную форму товара с артикулом, названием и
  приходной ценой. Цена продажи задаётся вручную, статус «Под заказ» включён,
  публикация выключена до проверки администратором. Сохранение использует
  существующее право `products.create` и обычную проверку уникальности артикула.
- Поиск и фильтры сохраняются при возврате из формы товара.

Заказы, корзина поставщика, смена контрагента и массовая публикация не вызываются.
Карточки товаров поставщиков сохраняют ссылки на фотографии МКС. Настройки
наценки не входят в этот контур. Остатки поставщика не записываются на наш склад.

## Как устроено подключение

Публичный JavaScript кабинета указывает обычный вход `POST /login/` с полями
`email` и `password`, и JSON-запросы `POST /api/filterinit/`, `POST /api/filter/`.
Карточка загружается через `GET /api/product/<id>/` в той же серверной сессии;
наша CRM предоставляет защищённый `GET /api/admin/mks/products/<id>`.
Поле поставщика `url` не используется для ссылок: отдельные `.html`-страницы
возвращают 404, а кабинет открывает товар в Angular-модальном окне по `id`.
В CRM возвращаются только поля товара; HTML описаний преобразуется в обычный
текст, а фотографии ограничены путями `/dbpics/` фиксированного домена МКС.
Используется Java HttpClient с отдельным CookieManager, без нового браузерного
контейнера. Адрес поставщика фиксирован: `https://mkskz.master.pro`.
Сессия сериализует запросы; при её истечении допускается один повторный вход.
Таймауты и размер ответа ограничены. Логин и пароль читаются из серверного
окружения и не возвращаются в API. Cookie и исходные ответы кабинета не
сохраняются приложением на диск и не логируются.

После заполнения `.env` проверены настоящий вход, общий каталог, поиск по
артикулу, категория, наличие, диапазон цен и сортировка. Ответ использует
`products.data`, `products.count`, `products.pagination`; фильтры категорий,
брендов, серий, линеек и акций содержат идентификаторы и названия поставщика.
Дополнительные характеристики поддерживаются через `params_vars/params_vals`
и `simple_params/maxmin`, когда поставщик возвращает их для категории.

В ответах МКС при ограничении цены встречается `count=0` и `pagination.total=0`
при непустой выборке. В таком случае интерфейс не показывает неверные итоги,
а разрешает следующую страницу по размеру выборки. Обычная выборка использует
точные итоги поставщика. Остатки являются сведениями поставщика на утро.

Неизвестный непустой формат товаров даёт явную ошибку, а не успешную пустую
таблицу. CAPTCHA или изменение протокола потребуют доработки подключения.

Проверка после заполнения: подключение → поиск известного артикула → категория
и фильтры → следующая страница → создание выбранного товара под заказ.
