# Уведомления о новых заказах

Звук в открытой админке и Web Push работают отдельно. Звук появляется после обновления списка уведомлений каждые 15 секунд. Web Push отправляется сервером после успешного завершения транзакции нового клиентского заказа всем активным пользователям с `orders.read`, у которых сохранены подписки устройств. Заказы от администратора не создают эти уведомления. Изменения статуса и цен клиентского заказа отправляются только его владельцу после успешного завершения транзакции.

## Настройка сервера

Один раз создайте пару VAPID-ключей P-256 в формате URL-safe Base64. Сохраните пару в закрытом файле `.env.production` на сервере, вне Git, с правами `0600`:

```dotenv
APP_WEB_PUSH_PUBLIC_KEY=<public key>
APP_WEB_PUSH_PRIVATE_KEY=<private key>
APP_WEB_PUSH_SUBJECT=https://mstop.kz
```

Обе production Compose-конфигурации передают эти настройки backend. Применяйте изменения через штатную blue/green-выкладку. Обычный `restart` не обновляет окружение контейнера. Ключи должны сохраняться между выкладками: их замена потребует переподключения устройств. Не выводите `docker inspect` окружения, `docker compose config` или содержимое `.env.production` в журналы.

Для фоновой доставки браузеру нужны HTTPS, активный service worker и разрешение на уведомления. Development Vite намеренно не регистрирует service worker: полноценную доставку проверяйте на production-сборке. Backend должен иметь исходящий доступ к push-сервисам браузеров по HTTPS.

## Подключение Android

Откройте `https://mstop.kz` в Chrome и войдите в свой аккаунт. В окне «Включить уведомления?» нажмите «Включить уведомления» и подтвердите разрешение браузера. После сохранения подписки окно закроется; постоянный блок состояния устройства в колокольчике не показывается.

Приглашение общее для клиентов и сотрудников. Оно проверяется при запуске авторизованного приложения, входе в оформление заказа, после перехода к оформленному заказу и входе в `/admin/orders`. Один показ расходует общий лимит: после «Позже», закрытия окна или отклонения системного запроса повторного приглашения в этой сессии не будет. Ограничение хранится в `sessionStorage` и сохраняется при обычной перезагрузке страницы. При закрытии вкладки/приложения начинается новая сессия; выход из аккаунта явно сбрасывает ограничение. Уже подключённое устройство синхронизируется без приглашения.

Каждый телефон и браузер подключаются отдельно. Если уведомления заблокированы, окно предложит разрешить их в настройках сайта и затем нажать «Проверить снова». Системный запрос браузера вызывается только по явному нажатию, до асинхронных действий; при запрете браузер сам повторно его не покажет. Для неподдерживаемого браузера или отсутствующих серверных ключей автоматическое приглашение не появляется.

## Диагностика

- «Отправка уведомлений ещё не настроена на сервере»: отсутствует полная VAPID-конфигурация backend.
- «Служба уведомлений ещё не готова»: service worker не активирован; обновите production-приложение.
- Ошибки отправки пишутся в backend-журнал с ID подписки и HTTP-статусом. Ответы 404/410 удаляют истёкшие подписки.
- Количество подписок можно проверить запросом `select count(*) from web_push_subscriptions;`. Не выводите endpoint и ключи подписок в журналы.
