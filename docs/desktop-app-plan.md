# План настольного приложения fresh-supply

Дата фиксации требований: 9 октября 2026 года.
В desktop 0.1.8 опубликованы исправления поиска/шрифтов PDF и
повторное обновление данных сайта. В 0.1.14 реализованы исправления установки Windows:
проверка полного пакета до замены, откат файлов, восстановление ярлыков,
сохранение режима установки и системное подтверждение прав. Добавлен CI-сценарий
настоящей установки и перехода с опубликованной 0.1.8 с сохранением локальной базы.
Подпись пакетов и интерактивный UAC на пользовательском ПК остаются отдельными
проверками; runtime Mac arm64 проверяется в native CI. По просьбе пользователя автоматические
проверки Windows отключены; сборка Windows x64 выполняется без тестового запуска.

## Состояние реализации

10 октября 2026: desktop 0.1.1 включает полный API-экспорт сайта и однократную
загрузку по URL в пустую локальную базу вместе с файлами. Реальный перенос между
двумя изолированными native runtime проверен через HTTP, включая вход, складские
связи, суммы, счётчики и повторный запуск. Инструкция:
[data-transfer.md](data-transfer.md).

12 октября 2026: добавлена команда «Файл → Обновить данные с сайта…» для полной
замены уже заполненной локальной копии. После проверки архива требуется отдельное
подтверждение; сохраняется резервная копия прежних данных и файлов. Отмена, ошибка
запуска после замены и ручное восстановление проверены на изолированном native
runtime Mac. Объединение изменений двух баз не выполняется.

13 октября 2026: повторное обновление переведено на объединение **сайт → десктоп**.
Локальные заказы сохраняются; для общей записи выбирается более позднее изменение,
а заказ и его состав применяются согласованно. Экспорт v2 содержит постоянные UID
и часы изменения; совпавшие независимые числовые ID и ссылки переназначаются.
Старые неоднозначные записи остаются локально с отчётом. Начисления и проведённые
поступления сверяются по журналам с пересчётом баланса и FIFO. Полная замена остаётся
отдельной командой с подтверждением и резервной копией. Отправки данных на сайт нет.

- Оболочка Electron автоматически запускает PostgreSQL/pgvector, локальный поиск
  и Java backend; общий React-интерфейс обслуживается с того же локального адреса.
- Подготовлен автономный runtime Mac с Java 21, Python и моделью E5; компоненты
  не зависят от установленного Homebrew или Docker. Для Windows предусмотрены
  отдельные переносимые бинарники; установщик x64 собран в native Windows CI
  с проверкой запуска runtime. Интерактивная установка на пользовательском ПК
  отдельно не проверена.
- Desktop-профиль использует локальное файловое хранилище и ограничитель запросов;
  серверный режим сохраняет MinIO/Redis. Существующие маршруты и права сохранены.
- Первый запуск запрашивает телефон и пароль; повторный запуск сохраняет аккаунт.
- В меню есть создание и восстановление копии, проверка обновлений и ссылка на
  GitHub Releases. Добавлены проверка новой версии при запуске, предложение
  «Обновить / Позже», загрузка с прогрессом и проверкой SHA-256, установка
  после резервного копирования. Механизм включён в выпуск 0.1.7.
- Реализованы копия перед миграцией, восстановление после неудачной миграции,
  восстановление прерванной замены каталогов и завершение дочерних процессов.
- Адаптированы системные уведомления настольной версии без PWA/service worker.
- Добавлена CI-сборка Mac arm64 и Windows x64 с готовыми пакетами и SHA256SUMS;
  тег `desktop-v<version>` создаёт черновик GitHub Release. Выпуск 0.1.5 опубликован;
  новый механизм обновления включён в выпуск 0.1.7.

Проверено: 39 backend-тестов для затронутых сценариев, 30 тестов оболочки и
обновлений, 23 теста уведомлений; frontend собирается. На настоящем локальном
runtime проверены вход, создание категории, файловое хранилище, перезапуск,
копирование и восстановление. Интеграционный тест включает настоящую успешную
миграцию схемы и намеренно неудачную миграцию с возвратом данных. Mac-приложение
открывает экран первичной настройки, форму входа и админ-панель.

При расширенной проверке обнаружены 3 падения существующего
`FileDownloadControllerTest` (ожидания Content-Disposition и mock для обхода пути);
они не исправлялись в этой задаче. Проверка установки Windows и системной доставки
уведомлений на обеих ОС пока не подтверждена. Инструкция:
[desktop/README.md](../desktop/README.md).

## Требования пользователя

- Самостоятельное приложение для Windows с установщиком `.exe`.
- Версия для macOS (`.app` / `.dmg`), чтобы пользователь мог тестировать на Mac.
- Сохранить существующий дизайн, маршруты, права и бизнес-функции сайта.
- Интерфейс, backend, локальная база и необходимые зависимости поставляются
  вместе с приложением. Пользователь запускает программу через один ярлык;
  ручной запуск серверов и установка инструментов разработки не требуются.
- Предусмотреть возможность «скачать скажем с гита последнюю версию и обновиться».
  Для пользователя это загрузка готовой сборки из GitHub Releases.
- Обновление сохраняет локальную базу, загруженные файлы и настройки.

## Локальная работа

Использовать общую кодовую базу сайта и настольных версий. При запуске приложение
автоматически запускает локальные компоненты, проверяет их готовность и открывает
интерфейс. Предусмотреть понятное сообщение при ошибке запуска, защиту от повторного
запуска и корректное завершение компонентов.

Текущие зависимости, которые нужно учесть: Java backend и среда Java,
PostgreSQL с pgvector, хранилище файлов MinIO, Redis, Python для импорта прайсов
и embedding-service с моделью. До выбора упаковки проверить совместимость
зависимостей с Windows и macOS; возможную замену компонентов оценивать по
сохранению функций и совместимости данных. Выбрана оболочка Electron.

Основные локальные операции должны работать без интернета. Внешние интеграции
требуют связи со своими сервисами. Интернет также необходим для загрузки обновлений;
его отсутствие не должно мешать запуску уже установленной версии.

## Выпуск и обновление из GitHub

Источник готовых версий: GitHub Releases репозитория
[ozLPanda/fresh-supply](https://github.com/ozLPanda/fresh-supply/releases).

- Публиковать версионированные сборки для Windows и macOS с указанием поддерживаемых
  архитектур, описанием изменений и данными для проверки целостности пакетов.
- После запуска проверять последний стабильный выпуск без блокирования работы
  при недоступной сети; предлагать «Обновить» и «Позже» только для новой версии.
- После подтверждения автоматически скачать и проверить пакет, создать копию
  данных и установить с перезапуском. Показывать прогресс и позволять отмену
  загрузки и подготовки до начала установки.
- В приложении предусмотреть текущую версию и действие «Проверить обновления».
  Показывать доступную версию и изменения; скачивать и устанавливать
  подходящий пакет по подтверждению пользователя. Предрелизы не предлагать как стабильные обновления.
- Готовые пакеты содержат согласованные версии интерфейса, backend и зависимостей;
  пользователю не требуется выполнять `git pull` или собирать исходники.
- Базу, файлы и настройки хранить отдельно от заменяемых файлов программы.
- Перед применением обновления корректно завершить операции и локальные компоненты,
  создать согласованную резервную копию базы, файлов и настроек.
- Применять миграции базы в рамках обновления и проверять готовность новой версии.
  При неудаче предусмотреть восстановление совместимой версии программы и данных
  из резервной копии; замена одного backend не является откатом миграций.
- Прерванная загрузка или недоступный GitHub не должны повреждать текущую установку.
- Проверять целостность и подлинность пакета перед применением. Если репозиторий
  закрытый, отдельно определить доступ к релизам без включения общего секретного
  GitHub-токена в приложение.

## Этапы реализации

1. Проверить зависимости и выбрать упаковку для обеих ОС, структуру локальных
   данных и управление запуском компонентов.
2. Подготовить локальную сборку для Mac и проверить основные бизнес-сценарии.
3. Подготовить Windows-сборку и проверить установку на чистой Windows.
4. Настроить воспроизводимый выпуск готовых пакетов в GitHub Releases.
5. Реализовано в исходниках: проверка при запуске, загрузка и установка по
   подтверждению, резервная копия, отмена и восстановление после ошибки подготовки.
   Проверить полный переход между установленными версиями на обеих ОС при выпуске
   следующей сборки. На Mac старый пакет сохраняется до подтверждения готовности.

## Приёмка

- На обеих ОС приложение устанавливается и запускается без инструментов разработки
  и ручного запуска backend или базы.
- Сохранены дизайн, права и основные бизнес-сценарии; локальные операции проверены
  без доступа к интернету.
- Версия N обновляется до N+1 из GitHub Releases без потери базы, файлов и настроек,
  включая релиз с миграцией схемы базы.
- Проверены прерванная загрузка, недоступный источник обновлений и ошибка миграции;
  приложение сохраняет рабочую установку либо восстанавливается из резервной копии.
- Windows и macOS проверяются отдельно, включая особенности файлов, печати,
  разрешений ОС и управления локальными процессами.
