# Price importer worker

Изолированный Python-воркер анализирует Excel-прайс и возвращает JSON для последующего review и импорта в `company_shop`. Воркер не изменяет книгу и не пишет в базу данных.

## Запуск

```powershell
python price_importer.py <input.xlsx> <output.json>
```

Поддерживаются `.xlsx` и `.xlsm`. Книга открывается через `openpyxl` с `read_only=True` и `data_only=True`. Для формул используется сохранённое в книге вычисленное значение; воркер формулы не пересчитывает.

Зависимости:

```powershell
python -m pip install -r requirements.txt
```

Код возврата `0` означает, что JSON сформирован. Ошибки данных остаются в JSON и не меняют код возврата. Код `2` означает операционную ошибку: неподдерживаемое расширение, отсутствие файла, повреждённую или непрочитанную книгу; итоговый JSON в таком случае не создаётся.

## Распознавание листа

Строка заголовков ищется в первых 30 строках и первых 50 колонках. Лист считается распознанным, если одна строка содержит:

- SKU: `код`, `артикул`, `sku`;
- хотя бы одну цену из списков ниже.

Название является необязательным price-only полем. Если присутствует заголовок `наименование`, `название`, `товар` или `name`, значение попадает в `name`; иначе `name` равно `null` и не считается ошибкой.

Ценовые aliases:

- розница: `цена`, `розница`, `розничная цена`;
- опт: `опт`, `оптовая цена`;
- крупный опт: `ско`, `крупный опт`.

Сравнение заголовков нечувствительно к регистру, пробелам и пунктуации. Если найдено несколько подходящих строк, выбирается строка с наибольшим количеством распознанных полей, при равенстве — самая ранняя. Нераспознанный лист всегда присутствует в `sheets` с ошибкой `unrecognized_sheet:no_supported_header`.

Повтор одного и того же распознанного поля в строке заголовков создаёт `duplicate_header:<field>` и в `sheets[].errors`, и в `errors` каждой строки этого листа. Это намеренно блокирует автоматическое применение неоднозначного mapping, даже если вызывающая сторона проверяет только ошибки строк.

## JSON-контракт, schemaVersion 1

```json
{
  "schemaVersion": 1,
  "sheets": [
    {
      "name": "Котлы",
      "recognized": true,
      "headerRow": 3,
      "columns": {
        "sku": 1,
        "name": 2,
        "price": 3,
        "wholesalePrice": 4,
        "bulkWholesalePrice": 5
      },
      "dataRowCount": 1,
      "errors": []
    }
  ],
  "rows": [
    {
      "sourceSheet": "Котлы",
      "sourceRow": 4,
      "sku": "00000001405",
      "name": "Котёл",
      "price": "1234.50",
      "wholesalePrice": null,
      "bulkWholesalePrice": "900",
      "errors": []
    }
  ],
  "errors": []
}
```

Номера колонок и строк — однобазовые, как в Excel. `dataRowCount` считает только строки, попавшие в `rows`.

Цены в JSON — положительная десятичная строка либо `null`. Строковый формат исключает потерю точности при передаче в Java `BigDecimal`. Пустая ячейка или ноль дают `null`, что позволяет вызывающей стороне сохранить существующее значение. Строка, где все цены пустые или нулевые, пропускается. Нечисловая, отрицательная, `NaN` или бесконечная цена даёт `null` и одну из ошибок:

- `invalid_price`;
- `invalid_wholesale_price`;
- `invalid_bulk_wholesale_price`.

`name` — строка либо `null`; пустое или отсутствующее имя означает, что вызывающая сторона должна сохранить существующее название товара.

SKU всегда строка. Для числовой ячейки с простым Excel-форматом вида `00000000000` восстанавливаются ведущие нули. Ключ дубля — SKU после Unicode-нормализации, схлопывания пробелов и `casefold`. Строки с одинаковыми или взаимодополняющими ценами схлопываются автоматически; `duplicate_sku` добавляется только строкам с конфликтующими ценами.

Другие стабильные ошибки строки: `missing_sku`, `cell_too_long:<field>`. При превышении 500 символов текст обрезается до 500, а строка остаётся только для review.

## Ограничения

- не более 100 листов;
- заголовки ищутся в первых 50 колонках; форматирование и изображения правее не мешают импорту;
- не более 10 000 непустых строк данных на книгу;
- не более 500 символов в используемой ячейке.

Workbook-ошибки находятся в корневом `errors`, ошибки конкретного листа — в `sheets[].errors`. При превышении числа листов книга не обрабатывается. При превышении числа строк результат содержит первые 10 000 строк и `row_limit_exceeded`; вызывающая сторона не должна применять импорт при непустом корневом `errors`.

## Тесты

```powershell
python -m unittest -v test_price_importer.py
```

Тесты используют только `unittest` из стандартной библиотеки; `openpyxl` создаёт временные книги и является единственной runtime-зависимостью воркера.
