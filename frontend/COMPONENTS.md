# Каталог компонентов frontend

Оформление общих компонентов перенесено из Hackalem; API и назначение компонентов сохранены. Токены и правила совместимости описаны в [визуальной системе](../docs/design-system.md).

Перед созданием компонента найдите здесь подходящий по назначению, затем прочитайте его актуальные props, стили и нужные места использования. Каталог помогает сузить поиск; исходный код остаётся источником истины, а отсутствие записи не доказывает отсутствие компонента.

Область охвата: все TSX-файлы `src/shared/ui`, самостоятельные компоненты форм и предметные компоненты в `features` и `pages/public`, извлечённые части складских форм и оболочка `AdminPage`. Страницы целиком, провайдеры, инфраструктура PWA/SEO и отдельные низкоуровневые обёртки сюда не включены.

Запись в разделе локальных компонентов описывает текущее расположение, а не готовность к межмодульному переиспользованию. При добавлении использования из другого модуля перенесите компонент в подходящую общую папку вместе с необходимыми стилями и зависимостями, обновите импорты и эту запись; универсальные UI-компоненты размещайте в `src/shared/ui`, предметные — в подходящем общем предметном каталоге.

При создании, переносе, существенном изменении или удалении компонента обновляйте каталог в той же задаче. На файл достаточно одной записи: экспортируемые компоненты, относительная ссылка и 1–2 предложения о назначении, применении и существенных ограничениях; не дублируйте полный API.
