# Самостоятельное развёртывание Ovoshi Help

Этот перенос не выполняет развёртывание, не подключает домен и не меняет firewall.
Производственная инфраструктура исходного магазина не используется автоматически.
GitHub workflow запускается только вручную и выводит справку; серверный таймер
не включается скриптом подготовки. Продакшен-сценарии перенесены как шаблоны и
не проверены на новом сервере.

`docker-compose.prod.yml` задаёт проект `ovoshi-help-prod` с собственными volumes
и сетями. PostgreSQL, MinIO, Redis и embeddings доступны только внутри Docker.
Backend и frontend опубликованы на loopback `18090` и `18091`. Внутренние имена
базы, Java-пакеты и миграции сохранены для совместимости бизнес-логики.

Перед самостоятельным развёртыванием:

1. Подготовьте отдельный хост/каталог и домен. Шаблон Nginx находится в
   `deploy/nginx/ovoshi-help.conf.template`; замените `__PROD_HOST__` и настройте TLS.
   В нём нет старого IP-адреса и технических публичных серверов исходного магазина.
2. Скопируйте `.env.production.example` в секретное окружение. Задайте реальные
   `POSTGRES_PASSWORD`, `MINIO_ROOT_PASSWORD`, `APP_BOOTSTRAP_ADMIN_PASSWORD`
   (16+ символов), origin в `APP_CORS_ALLOWED_ORIGINS` и `APP_SEO_SITE_URL`.
   Пустые обязательные значения останавливают Compose до запуска.
3. Настройте резервное копирование, проверьте сборку frontend и backend-тесты.
4. Проверьте конфигурацию без запуска:

   ```bash
   docker compose --env-file .env.production -f docker-compose.prod.yml config --quiet
   ```

Скрипты `deploy/production/` используют только новый namespace `ovoshi-help`,
каталог `/opt/ovoshi-help-repo`, состояние `/var/lib/ovoshi-help`, Nginx upstreams
`ovoshi_help_backend` / `ovoshi_help_frontend` и отдельные системные units.
Слоты blue/green используют `18092–18095`. У них должен быть отдельный Git remote;
не указывайте репозиторий исходного магазина. `provision-blue-green.sh` требует
явно передать новый домен; автоматическое polling-развёртывание выключено.
Включение таймеров, установка Nginx, публикация и запуск скриптов — отдельная
операционная задача после проверки на целевом сервере.

Локальные Windows-скрипты старой LAN-публикации отключены с пояснением; для
loopback-портов изменения firewall и установка доверенного CA не нужны.
